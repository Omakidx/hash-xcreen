Run on the server

Open a root shell on 203.0.113.142 and run the command. The installer checks the server, installs the agent and opens port 443, then asks for the token.

1. Run this command on the server, in a root shell
curl -fsSL https://github.com/Omakidx/hash-xcreen/releases/download/channel-stable/install.sh | sudo sh -s -- --pair --distro ubuntu-24.04 --desktop xfce --apps developer --user alex --docker --cpu 3 --memory 5G --backup off
Holds no token and no secret, so it is safe in shell history and server logs.
2. Paste this token when the installer asks for it
hxt1-aaaqeayeaudaocajbifqydiob4ibceqtcqkrmfyydenbwha5dypsaijcemsckjrh
One-time. Works once and expires 15 minutes after the installer takes it. Nothing is shown while you paste it.
Waiting for the server…
Looking for the agent at 203.0.113.142:443. This starts as soon as the installer opens the port.
Keyboard order: Copy command, Copy token, Cancel, Back. Copy buttons announce "Copied" in a live region and clear the clipboard text from the page after use.
Accessibility: the token is selectable text, never placed in a link or the title bar. It is not logged by the app.
The command is a single line in the app (wrapped here). Token shape: hxt1- plus 64 lowercase base32 characters (a made-up sample).

Enter pairing code

On the server, install.sh --interactive printed a code and the server’s addresses. A new code: hx-agent pairing code.

One of the addresses the installer printed.
Eight characters, valid for 15 minutes. Case and the dash do not matter.

After pairing, the server appears on Home and you connect with your PIN.

Keyboard order: Server address, Agent port, Pairing code (auto-uppercased), Back, Pair.
Accessibility: the code field accepts paste with or without the dash.

Pairing code: failed

The server never says which reason applies (protocol 4: an unknown, expired or spent secret fails the same way), so the message lists the possibilities.
