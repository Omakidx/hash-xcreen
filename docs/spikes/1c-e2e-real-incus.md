# Spike 1C: the whole stack on a real Incus desktop

Status: run complete (2026-11-21), local Incus 6.0.0, three clean runs in a row (the desktop build included each time; the last two on the committed code). **Verdict: PASS, with one product bug found and fixed (a desktop built on the server did not boot into what was built), one intermittent observation that is still open (a WebSocket close code), and the items in section 9 not run.** This is the first time every part-3 component ran together; until now each had been tested against fakes or in-process stand-ins. Contracts under test: [ipc.md](../ipc.md) (privd command set, the link of sections 11 and 12), [architecture.md](../architecture.md) section 5, and [proxy-device spike](1c-proxy-device.md) for the link device.

Code: `apps/hx-agent/tests/e2e_real_incus.rs` and `apps/hx-agent/tests/e2e_common/mod.rs`. Evidence pictures: [`1c-e2e-real-incus/`](1c-e2e-real-incus/).

## 1. Goal

Run, with nothing faked on the path of a user, the flow "create the desktop, pair a device, log in with the PIN, see and drive the desktop":

```text
client (hx-crypto + hx-transport) --QUIC or WebSocket--> hx-gatewayd (the binary of the crate
  as built for the tests, seccomp enforce) --link socket = Incus proxy device--> hx-session (host-built release binary,
  started by systemd socket activation inside the container) --> Xorg + XFCE of the real desktop
hx-gatewayd --privd socket--> hx-privd (in-process, real Incus) --> Incus REST
```

Acceptance: pair; PIN login; `ViewConfig` answered by `StreamInfo`, an IDR and P frames of the real desktop at the right size, decoded with FFmpeg to prove they are a picture; key and mouse in the container; clipboard and one file each way; resize; takeover by a second device; revoke mid-stream; container stop and start with a reconnect; measurements; clean-up of every object.

## 4. The binary in the container

The host and the container are both Ubuntu 24.04 (glibc 2.39). `readelf -d` shows the release binary needs only `libavutil.so.58`, `libavcodec.so.60`, `libgcc_s.so.1` and `libc.so.6`. In the container `ldd` reported **0 unresolved** libraries after `apt-get install libavcodec60 libavutil58` (which pulls x264, X11 and the rest); the test asserts that count. The binary was not built inside the container. A `.deb` must declare `libavcodec60` and `libavutil58` (or the distro's names for them) as dependencies, and the Debian 12 and 13 and Ubuntu 26.04 recipes have different FFmpeg sonames: the package is per distro, as ipc.md 6.11 already says.

## 7. Bugs found

### 7.1 FIXED: a desktop built on the server did not boot into what was built

First run, step "hx-session.socket active": `inactive`, although enabled. In the kept container `hx-xorg.service` was inactive as well, uptime 4 minutes, and after `RestartSession` and a first dial `hx-session.service` failed with `226/NAMESPACE`: `Failed to set up mount namespacing: /var/lib/hx-session/clipboard: No such file or directory`.

Cause: the build stage only *enables* units (`systemctl enable`, never `--now`) and writes `tmpfiles.d` entries, which are applied at boot. `build_on_server` never booted the container again, so after `CreateDesktop` (path Build) there was no Xorg, no XFCE, no `/var/lib/hx-session/{received,clipboard}`, and the link's service could not start however often it was restarted. The prebuilt path boots into its image and is not affected; `incus_real_session.rs` had always restarted the container by hand ("boot into the session"), which is why nothing saw it.

Fix (commit `dba3bf0`): `build_on_server` restarts the container after the post stage and waits for `running` again. Regression test `build_on_server_restarts_the_container_after_the_post_stage` in `crates/hx-provision/tests/orchestrate.rs`: it failed before (`["start"]`), it passes after. Cost: one container restart (about 5 s) on the build path. The three clean runs above ran with the fix.

### 7.2 OPEN, intermittent: a WebSocket client may see `INTERNAL_ERROR` where `UNAUTHORIZED` is expected on revoke

One occurrence in a kept-desktop development run: the tablet's WebSocket connection, revoked mid-stream while the desktop was busy, reported `closed.code == InternalError` instead of `Unauthorized` (the assertion `left: InternalError, right: Unauthorized`). The close reason was not printed at that point, so the evidence is the code only. It did not recur in the next development run and the 3 clean runs (4 more WebSocket revokes, all `Unauthorized`, reason "device revoked", `by_peer=true`), nor in an in-process probe that revoked a streaming WebSocket client under heavy load 10 times in a row (all `Unauthorized`; the probe was scratch code and is not committed). The QUIC path never showed it.

Hypothesis, not confirmed: `hx-transport`'s WebSocket writer records `InternalError` ("connection lost") when a write fails, and the first recorded close wins; if the TCP connection is torn down while the client is still acknowledging frames, the client can record the write error before it has processed the server's close frame. The protocol says the client must see the close code (it decides whether to offer re-pairing). Next step for the owner of `hx-transport`: print `closed.reason` on the failing path (the test does now: `revoke ... reason ...`) and, if it is "connection lost", have the writer defer to a close frame that is already queued in the reader. Not fixed here: it needs a deterministic reproduction first.

### 7.3 Observations (not bugs of this change)

* **A desktop built without the `hx-session` package** (the current state: there is no `.deb`) is `ready` and, with fix 7.1, boots with Xorg and XFCE running, but `hx-session.socket` has nothing to start: the first dial fails with `203/EXEC`. `CreateDesktop` says so in its warnings ("run InstallSession once it is"). Pushing the binary and `RestartSession` (the `reset-failed` step matters) brings it up, which is what the test does.
* **The X screen stays resized.** After a client resizes (RandR) and leaves, the X screen keeps that size until the container restarts; the next client's native size is then the resized one. Possibly intended ("resize to the client window"); the design does not say whether it is restored when the last client leaves.
* **An idle desktop sends no frames at all** (0 in 10 s). A client must not treat video silence as a fault; ServerStats (when enabled) is the liveness signal.
* **`incus file push --create-dirs` makes `/usr/lib/hx-session` 0750.** The package must install it 0755, because the service runs as the desktop user (the test does the `chmod`; without it the service fails `203/EXEC` with `Permission denied`).
